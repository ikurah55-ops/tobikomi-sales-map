# 飛び込み営業マップ

生命保険・医療保険の飛び込み営業のための、スマホ向けWebアプリです。

- 国勢調査の町丁目データから「訪問すべきエリア」をスコア化して地図に色分け表示
- 現在地にピンを立てて、訪問記録(在宅・反応・他社の営業・天気・メモ)を30秒で記録
- 曜日×時間帯の在宅率、町丁目別の成績などを集計して見える化
- 記録は端末の中(IndexedDB)だけに保存。サーバーやAI APIは使いません
- ホーム画面に追加でき(PWA)、電波が弱くても記録できます

> **今入っている統計データはダミー(架空の数値)です。** 実データの入れ方は「実データの入手と更新」を見てください。

---

## 1. 起動方法(Windows / PowerShell)

Node.js 20 以上が必要です。

```powershell
npm install
npm run dev
```

表示された `http://localhost:5173/` をPCのブラウザで開きます。
同じWi-Fiのスマホから試すときは、表示される `Network:` のアドレス(例 `http://192.168.x.x:5173/`)を開きます。
※ スマホで位置情報を使うには HTTPS が必要なので、外回りで使うときは GitHub Pages に公開したものを使ってください。

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発用サーバー |
| `npm run build` | 本番用ビルド(`dist/` に出力) |
| `npm run preview` | ビルド結果の確認 |
| `npm run data:dummy` | ダミーの生データを作って前処理まで実行 |
| `npm run data:build -- --city 06201` | 実データの前処理(市区町村1つ) |
| `npm run data:build -- --pref 06` | 実データの前処理(県内すべて) |
| `npm run data:inspect -- --pref 06` | 生データの列見出しを表示(設定の調整用) |
| `npm run icons` | アプリアイコンを作り直す |

## 2. 使い方

### 地図
- **📍 現在地にピンを立てる**(右下の大きいボタン)→ 在宅/不在 → 反応 → **保存** で記録完了
  - 「不在」「応答なし」なら反応は省略できます
  - 「訪問お断りの意思表示」を選ぶと、自動で再訪禁止になります
  - 天気はその日の前回の記録を引き継ぎます
- **地図を長押し**(PCは右クリック)でも、その場所にピンを立てられます
- ピンをタップ → 訪問の履歴、「不在だった時間帯」のヒント、家の情報の編集、訪問の追加
- 町丁目をタップ → スコア・順位・各指標と市平均の比較
- 右上のボタン: 色分けのオン/オフ、ピンの絞り込み、凡例
- ◎ボタン: 現在地に移動して**追従モード**(地図を指で動かすと自動でオフ)
- 画面上部: 地域の切り替えと、今いる町丁目の名前・スコア

### ピンの色

| 色 | 状態 |
|---|---|
| 緑 | 成約・アポ獲得 |
| 青 | 話を聞いてくれた・資料を渡した |
| 黄 | 不在・応答なし(まだ会えていない) |
| オレンジ | 断られた |
| 灰色(×) | 再訪禁止 |
| 赤い「再」バッジ | 再訪予定日が今日以前 |

最新の訪問結果で色を決めますが、最新が「不在」でも過去に会えていれば、最後に会えたときの結果の色にしています(黄色は「一度も会えていない家」だけにするため)。

### ランキング・分析・設定
- **ランキング**: スコア順の町丁目一覧。主な理由・訪問件数・在宅率つき。タップで地図へ
- **分析**: サマリー、曜日×時間帯の在宅率(平日9〜18時台)、町丁目別の成績、天気別・住居の種類別
- **設定**: プリセット、狙う年齢層、指標の重み、比較する範囲、地域データ、位置情報、バックアップ

## 3. スコアの計算

各指標を、比較する範囲(初期値は表示中の市区町村)の町丁目の中でパーセンタイル(0〜100)に変換し、重みをかけて合計します。

| 指標 | 初期の重み | 計算 |
|---|---|---|
| 夫婦と子どもの世帯の割合 | 30% | 夫婦と子供から成る世帯 ÷ 一般世帯 |
| 狙う年齢層の人口割合 | 20% | 選んだ5歳階級の人口 ÷ 総人口 |
| 18歳未満の子がいる世帯の割合 | 20% | 18歳未満世帯員のいる一般世帯 ÷ 一般世帯 |
| 持ち家一戸建て率 | 15% | 持ち家の一戸建て ÷ 主世帯 |
| 人口増加率 | 15% | (2020年 − 2015年) ÷ 2015年 |

- 値がない(null)指標は、残りの指標で重みを按分し直します
- 世帯数30未満・秘匿(X など)の町丁目は「データ不足」としてランキングから外します
- 2015年と2020年で境界が変わった町丁目は、人口増加率を null にします
- 地図の5段階の色は、順位の上位20%ずつで分けています

## 4. 実データの入手と更新

統計は[政府統計の総合窓口(e-Stat)](https://www.e-stat.go.jp/)から無料でダウンロードできます。ファイルは `data/raw/` に置きます。

### 4-1. 統計表(CSV)
1. e-Stat の「地図で見る統計(統計GIS)」→「データダウンロード」を開く
2. 「国勢調査」→「2020年」→「小地域(町丁・字等別)」を選ぶ
3. 次の表を、都道府県「山形県」で1つずつダウンロード(ZIP を解凍した `.txt` を `data/raw/` に置く)

| 必要なもの | 表の名前 | ファイル名 |
|---|---|---|
| 世帯数 | 男女別人口総数及び世帯総数 | `tblT001081C06.txt` |
| 年齢(5歳階級)別人口 | 年齢(5歳階級、4区分)別、男女別人口 | `tblT001082C06.txt` |
| 世帯の家族類型 | 世帯の家族類型別一般世帯数 | `tblT001084C06.txt` |
| 持ち家 | 住宅の所有の関係別一般世帯数 | `tblT001085C06.txt` |
| 一戸建て | 住宅の建て方別世帯数 | `tblT001086C06.txt` |
| 2015年の人口(増加率用) | 2015年 年齢(5歳階級、4区分)別、男女別人口 | `tblT000849C06.txt` |

ダウンロードURLの形(`06` が都道府県コード):
- 統計表: `https://www.e-stat.go.jp/gis/statmap-search/data?statsId=T001082&code=06&downloadType=2`
- 2020年境界: `https://www.e-stat.go.jp/gis/statmap-search/data?dlserveyId=A002005212020&code=06&coordSys=1&format=shape&downloadType=5&datum=2000`
- 2015年境界: 上の `A002005212020` を `A002005212015` にする(解凍した `h27ka06.*` を置く)

**2020年の小地域集計で分かったこと(2026年11月に山形県で確認)**
- 男女別の就業者数・労働力状態の表がないため、仕様の「女性の非就業率」の代わりに**「18歳未満の子がいる世帯の割合」**(T001084 の列)を使っています
- 持ち家×一戸建ての掛け合わせ表がないため、**持ち家一戸建て率は「持ち家率 × 一戸建て率」で近似**しています
- 5歳階級は70〜74歳まで(その上は75歳以上)
- 丁目のない町は統計表の KEY_CODE が9桁なので、境界の11桁と自動で読み替えています

### 4-2. 境界データ(シェープファイル)
1. 同じ「データダウンロード」→「境界データ」→「小地域」→「国勢調査」→「2020年」→「小地域(町丁・字等別)」→「世界測地系緯度経度・Shapefile」→「山形県」
2. 解凍した `r2ka06.shp` `.dbf` `.shx` `.prj` を `data/raw/` に置く
3. 2015年の境界(`h27ka06.shp` など)も置くと、境界の変わった町丁目をより正確に判定できます(なくても動きます)

### 4-3. 前処理を実行

```powershell
npm run data:inspect -- --pref 06      # 列の見出しを確認
npm run data:build -- --city 06201     # 山形市だけ
npm run data:build -- --pref 06        # 山形県の全市区町村
```

- 出力: `public/data/regions/06/06201.json`(市区町村ごと)と `public/data/regions/index.json`(一覧)
- 境界は mapshaper で軽量化(`simplify 15%`)して GeoJSON にしています
- **e-Stat の表番号や列の見出しは年によって変わることがあります。** 「列が見つかりません」と出たら、表示された見出しを見て `scripts/preprocess.config.json` の正規表現やファイル名を書き換えてください

### 4-4. ダミーデータに戻す
```powershell
npm run data:dummy
```

### 4-5. 新しい国勢調査が出たとき
`scripts/preprocess.config.json` の `dataYear` と表のファイル名を新しい年に合わせて前処理し直し、公開し直します。アプリは `index.json` のデータの年が端末の地域データより新しいと、設定画面に「更新あり」と表示します。

## 5. 別の地域を追加する手順

例: 天童市(06210)

1. 山形県の生データ(4章)が `data/raw/` にあれば、そのまま
   ```powershell
   npm run data:build -- --city 06210
   ```
   別の県なら、その県の表と境界を置いて `--pref <県コード>` で実行(`tblT001082C{県コード}.txt` のように自動で読み替えます)
2. `index.json` に追記されるので、ビルドして公開し直す
3. アプリの **設定 → 地域の追加** で都道府県 → 市区町村を選び「ダウンロード」
4. 地図上部の地域メニューで切り替え。「📍 現在地から選ぶ」で最寄りの地域を選べます。現在地のある地域へは自動で切り替わります(設定でオフ可)

- 地域データは端末(IndexedDB)に保存されるので、オフラインでも使えます。設定画面から更新・削除できます
- 訪問ピンは地域データがなくても全国どこでも立てられます。あとでその地域のデータを読み込むと、町丁目を自動で判定し直します

### データの置き場所を変える(容量が大きくなったら)
全国分の前処理ファイルは大きくなるので、Cloudflare R2 などの静的ストレージに置けます。

1. `public/data/regions/` の中身をストレージにアップロード
2. ストレージ側で CORS を許可(アプリの公開URLからの GET)
3. `.env.example` をコピーして `.env` を作り、`VITE_DATA_BASE_URL=https://…/regions/` を書いてビルドし直す

## 6. GitHub Pages への公開手順

1. GitHub で新しいリポジトリを作る(例 `tobikomi-sales-map`)
2. このフォルダで
   ```powershell
   git init
   git add .
   git commit -m "first commit"
   ```

## 7. バックアップ方法

記録はその端末のブラウザの中だけにあります。機種変更・ブラウザのデータ消去・アプリの削除で消えるので、定期的にバックアップしてください。

- **設定 → バックアップ → JSONでバックアップ**: 全記録をファイルに保存(Googleドライブ等に置いておく)
- **JSONから復元**: 同じIDの記録は上書き、ない記録は追加(今ある記録は消えません)
- **CSVで書き出し**: Excel で開ける一覧(1行 = 1回の訪問)

## 8. プライバシー

- 訪問記録・位置情報は端末の外に送信しません。移動の軌跡も保存しません
- アプリが画面に出ていないときは位置情報の取得を止めます
- 入力欄に氏名・電話番号・健康状態など個人情報は記録しないでください

## 駐車場のある店のデータ

コンビニ・スーパー・本屋・ホームセンター・ドラッグストア・モールのうち、駐車場の大きい店を OpenStreetMap から抜き出して市区町村ごとの JSON にします(地域データと同じく、アプリの設定画面から市区町村ごとにダウンロード)。

```powershell
npm run data:facilities -- --pref 06            # 山形県(data/raw/osm-06.json があれば再利用)
npm run data:facilities -- --pref 06 --refresh  # Overpass API から取り直す
```

- 先に `npm run data:build -- --pref 06` で地域データを作っておく(店の市区町村の判定に使う)
- 出力: `public/data/facilities/06/06201.json` と `public/data/facilities/index.json`
- 台数は駐車場の面積 ÷ 25㎡ の推定値。店から一定距離(コンビニ40m〜モール180m)にある駐車場を、いちばん近い店1つに割り当てる
- 有料駐車場・関係者以外不可の駐車場、駅の売店は除く。コンビニは80台を超える駐車場を数えない(駅・病院などの駐車場が隣にあることが多いため)
- 10台未満の店はデータに入れない。アプリでは初期値「30台以上」で、設定で10〜100台に変えられる
- 地図データに駐車場が描かれていない店は出ない(山形県では店1,058件のうち290件)
- 「使える駐車場」の登録と「地図から消した店」は端末内(IndexedDB)に保存し、JSONバックアップにも含める
- 店のデータにない駐車場も、地図を長押し →「ここを使える駐車場として登録」で追加できる(緑の P★)

## 足跡記録

地図の「👣 足跡記録開始」を押すと、「記録終了」を押すまでの移動を記録します(`src/hooks/useTrackRecorder.ts`)。

- 位置は精度50m以内のものだけを使い、立ち止まっている間のふらつきや GPS の飛びは除きます。5分以上空いたところは線をつなぎません。
- 記録中は Wake Lock で画面を消さないようにします。ブラウザの制約で、画面オフ・別アプリ表示中は位置を取れないことがあります。
- 点は IndexedDB(`tracks`)に少しずつ保存するので、アプリを閉じても終了していなければ続きから記録します。
- 終了すると、範囲記録と同じ項目(日時・訪問した件数・話ができた件数・再訪の予約ができた件数・成約した件数・メモ)で営業記録を保存します。件数の初期値は、記録していた時間帯のピンの訪問記録から数えます。
- 過去の足跡は地図右の「足跡」から一覧・地図表示・編集・削除ができます。「絞込」→「以前の足跡を表示」で期間を選んでまとめて地図に出せます。JSON バックアップにも入ります。

## 範囲の営業記録

地図右の「✍️ 範囲」を押してから地図を指(マウス)でなぞり、「この範囲で確定しますか?」で「はい」を押すと、囲んだ範囲に営業記録を保存できます(確認中はピンチ・ズームで縮尺を変えられ、「修正する」で描き直せます)(`src/components/DrawOverlay.tsx`、`AreaRecordSheet.tsx`)。

- 記録内容: 日時、訪問した件数、話ができた件数、再訪の予約ができた件数、成約した件数、メモ。
- 範囲の中にピンがあれば、その日のピンの訪問記録から件数を入れるボタンが出ます(再訪予約 = アポ獲得・成約)。
- 保存した範囲はオレンジの点線で地図に出て、タップすると編集・削除できます。「絞込」で表示のオン・オフと期間を選べます。JSON バックアップにも入ります。
